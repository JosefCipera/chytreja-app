## How the audit was done, and its limits

- **No read-only SQL connection exists in this environment** (Supabase MCP did not connect; no database URL, `psql` or Supabase CLI). `scripts/privacy-preflight.sql` was therefore NOT run. Substitute used: the PostgREST OpenAPI description of the `public` schema (metadata only, no rows), read with the application's server key through `GET` only. It shows relations, columns, types and foreign keys between exposed relations. It does NOT show other schemas, RLS flags, policies, triggers, FK delete rules or FKs to other schemas.
- Supabase Storage: bucket metadata and object listing through the Storage API with the same key; names were processed locally and only generalized patterns are reported.
- Public, unauthenticated probes (HTTP status only) and static analysis of the repository.
- `gcloud` is logged in but cannot refresh its token here (TLS certificate verification error), so Firebase/GCP could not be read.
- Vercel, Supabase dashboard and provider consoles were not accessible.
